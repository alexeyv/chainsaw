- (direction) Four orthogonal axes named: substrate (herdr/tmux/subagents), platform (claude/codex/grok), model (opus/fable/grok-4.6), role (lead/commentator/implementer); user's terminology, platform not model
- (decision) SessionRuntime is the substrate axis and was correctly scoped from the start; it stays untouched. The new axis is a per-platform session adapter
- (decision) Substrate is herdr only for this work; tmux/orca remain possible but unbuilt
- (constraint) Subagents are rejected as a substrate: they pin every session to one platform, write no per-session transcript (sidechain entries in the parent), and have no visible pane - chainsaw's observability and human-takeover model both depend on those
- (decision) Platform and model are chosen per role at launch, passed as CLI flags by the lead when it invokes the coordinator - not a config file, because the lead already composes these calls and a config would be a second place to keep in sync with the prompt
- (constraint) Platform must be persisted on the session row: the daemon parses each session's transcript on every poll long after launch, so the launch flag alone is insufficient
- (decision) Scope is Codex only; Grok is dropped at user direction. Success is a run with Claude lead and commentator plus Codex implementers
- (note) Evidence gathered from Codex 0.150.1 installed locally and a real rollout file, not from memory
- (constraint) herdr already supports --kind codex (verified in its --kind possible values), so the substrate needs only a per-platform kind string
- (constraint) Codex loads SKILL.md natively (observed a skills_instructions developer message in a live rollout), so the skill layout survives; only prompt wording needs retuning
- (constraint) Codex writes ~/.codex/sessions/YYYY/MM/DD/rollout-<ISO>-<uuid>.jsonl - date-partitioned, not per-project - so chainsaw's single per-run logs_dir has no analogue and must become adapter-resolved per-session paths
- (constraint) The supervisor's SQLite database currently lives inside Claude Code's transcript directory; it must move to a chainsaw-owned location because no such per-run directory exists for Codex
- (constraint) Codex records event_msg/token_count with total_token_usage.total_tokens and model_context_window per turn - richer than Claude Code, so thresholds can become a fraction of the window rather than hardcoded token counts
- (constraint) Codex has no --disallowedTools equivalent; tool narrowing for implementers must be expressed through the prompt and sandbox/approval flags instead
- (constraint) Codex auto-compacts and has no /compact to send, so the supervisor's commentator compaction push must become platform-specific behaviour rather than an unconditional prompt
- (constraint) Codex transcript entries are type=response_item with payload.type of message/agent_message/reasoning/custom_tool_call and content[].type=input_text, unlike Claude's type=assistant with message.content - so commit scraping, prompt-landing and mention detection all need per-platform predicates
- (note) Codex agent_message payloads can carry encrypted_content, so text scraping of a Codex transcript is not guaranteed complete
- (constraint) In a heterogeneous run the commentator reads implementer transcripts written by a different platform, in a different tree and format - the adapter must hand it resolved paths and name the format instead of pointing at a directory
- (constraint) The lead is registered rather than launched, so its platform arrives as a daemon flag; observe_lead reads the lead transcript for the stop threshold and cannot infer the platform otherwise
- (constraint) Defaults must keep every existing SKILL.md invocation working unchanged: platform defaults to claude, model to today's opus, and the sessions table migration defaults existing rows to claude
- (assumption) Spec folder placed at docs/specs/ because chainsaw has no _bmad installation and therefore no configured output_folder
- (capability) CAP-1 the lead chooses platform and model per role when it invokes the coordinator; success: a single run starts a Claude commentator and a Codex implementer from flags alone
- (capability) CAP-2 the supervisor reads any supported session's transcript through that session's platform adapter; success: context size, new commits, prompt landing and sha mentions are all resolved correctly against a real Codex rollout and a real Claude transcript
- (capability) CAP-3 a session's platform survives process restarts; success: a daemon restarted mid-run still parses a Codex implementer's transcript without being told the platform again
- (capability) CAP-4 supervisor durable state lives in a chainsaw-owned location independent of any platform's transcript directory; success: a run whose sessions are all Codex still has a database, and it is not under ~/.claude
- (capability) CAP-5 existing Claude-only runs are unaffected; success: every command in the current SKILL.md works unchanged with no new flags, and a database from before the change opens and reads
- (capability) CAP-6 a heterogeneous run completes end to end; success: Claude lead and commentator with Codex implementers takes a task from created to accepted, with commentary delivered against the Codex commit
- (decision) Story 1: relocate supervisor durable state out of the platform transcript directory - foundation, unblocks everything, no behaviour change
- (decision) Story 2: introduce the SessionAdapter trait with a ClaudeCode implementation, moving logs.rs behind it as a pure refactor
- (decision) Story 3: persist platform and model on the session row with a migration defaulting existing rows to claude
- (decision) Story 4: add --platform and --model flags to launch, start-commentator and daemon, wiring them to the herdr kind and launch argv
- (decision) Story 5: implement the Codex adapter - date-partitioned transcript discovery, token_count context, commit scraping, prompt landing, mentions
- (decision) Story 6: make compaction pressure and context thresholds platform-specific, expressed against the reported context window where one exists
- (decision) Story 7: update SKILL.md and commentator.md for heterogeneous runs, handing the commentator resolved paths and the format name
- (decision) Story 8: validate one end-to-end heterogeneous run - Claude lead and commentator, Codex implementer, task through to accepted
